# MITM review 12: routing semantics correction and stop gate

User decision: HTTPS decryption is orthogonal to routing. Do not ask for a separate egress policy. Raise product/architecture contradictions at discovery, before committing to a workaround.

## Source evidence (Mihomo v1.19.34)
- tunnel/tunnel.go handleTCPConn at 554 resolves the original metadata to proxy and rule, then applies hosts/Pure and calls proxy.DialContext at 577. resolveMetadata at 317 performs original source IP/port process lookup, DNS, and rule/mode selection. match at 654 handles pass/rematch and group unwrapping. constant/metadata.go contains process, UID, inbound, addresses, source port, special rules and DNS fields. adapter/outbound/http.go builds CONNECT from metadata.RemoteAddress; it does not transmit an original decision. 
- Existing NetVerge overlay prepends TUN hostname interception and return policy; this changes precedence, can override REJECT, and loses original process context on the second connection. It was an explicitly limited lab, not an acceptable user feature. No generic YAML-only rewrite can reconstruct every original per-connection decision.

## Immediate correction
- Compile-time desktop gate closed; ordinary profile generation strips MITM extension and does not add the legacy override. Stale generated reserved overlays are refused at worker startup. Normal rule/mode guards do not treat the paused MITM as active. Existing laboratory code/tests are retained as historical transport experiments, not evidence of route equivalence.
- Remove outlet selector, page-wide save and discard. Standalone two-column layout: CA/status left, hostname list right, top disabled switch and clear routing-pause explanation. Add/edit/delete saves host-only inactive settings (revision-checked). Existing legacy enable/policy is not displayed or honored; backend rejects enabling or setting policy during the gate. No system trust writes, no live reconfiguration. Preserve old file until deliberate host edit. No false promise that restart enables decryption.
- Keep wire fields temporarily for migration/contract compatibility. Existing fixed-policy tests only exercise the historical internal overlay; do not approve deployment on that basis.

## Next implementation gate
1. Prototype a small pinned Mihomo integration after original resolveMetadata and before dialing. Retain original proxy object, rule and immutable copy of full dial metadata, not a client-supplied process name or group string. Do not intercept denied connections (including nested REJECT) or non-selected/non-TLS traffic. Preserve standard adapter behavior, retry, cancellation and DNS semantics.
2. Evaluate Whistle per-tunnel/per-request upstream transport with a capability bound to original authority, generation, connection lifetime and selected decision. A separate authenticated private dial broker consumes only the capability, never re-runs routing from a Whistle socket or permits caller-selected egress. No global direct fallback. Account for HTTP keep-alive, connection pooling, multiple outbound dials and original connection teardown. Prefer bounded capabilities; no arbitrary headers accepted from apps. Verify implementation feasibility against both pinned upstreams before claiming support.
3. Compare ordinary and decrypted flows using actual controlled endpoints: domain/IP/source/IN-NAME/process/UID rules, REJECT, nested groups, dynamic selection, DNS hosts/Pure, retries, core reload/worker loss, nonselected bypass, no unauthorized fallback. Actual Windows/macOS TUN and explicit proxy ingress are separate tests. Include statistics and original rule attribution. Linux last. Only reopen desktop gate when equivalent behavior is demonstrated; not merely when old network tests pass.

## Three-dimensional review
Functionality: removes incorrect UX and prevents known incompatible routing, does not yet implement transparent routing. Architecture: single owner Mihomo; no duplicate rule engine, no manual policy workaround. Security/stability: legacy activation rejected and stale overlay not accepted; native trust unchanged; pending core broker and end-to-end tests block activation/release. CI required.
