# MITM desktop review 06: read-only IPC and public certificate

Baseline cedb5cb passed all seven CI jobs, six focused Rust tests, actual Linux TUN and four-platform explicit CONNECT tests, with local authenticated health round trips. No change to the user-selected Clash YAML direction.

## Functionality
- Register `get_mitm_status` and `get_mitm_public_ca` in the existing Tauri/Specta command registry. Status is a small snapshot of last observed health, current Core generation association, attempt budget and public CA fingerprint. It never waits for the process mutex. Public CA returns the last verified certificate (PEM plus SHA-256 of DER) or null; no path input, private key or trust installation.
- Worker readiness now carries the canonical DER of the verified self-signed CA. Node checks CA flag, self-signature, validity and file location; Rust parses and re-encodes public DER. A changed CA within the same desktop session prevents replacement activation. Existing CA generation/storage remains Whistle's responsibility.
- Add regression checks for public CA encoding, continuity, malformed DER, IPC redaction, backup entry rejection and real process fixture. Cross-platform checks and generated frontend contract pending. The contract is generated by the existing Specta generator in CI and must be reviewed and committed before frontend use, not edited by hand.

## Architecture/reuse
One Session owns process and CA. Lightweight public snapshot only mirrors observed state and is checked against the existing Core generation. Reuse Rustls, SHA-256, Node X509Certificate, Tauri IPC and the existing contract generator. No new dependencies or alternate config format. The public certificate export is data only; the future UI can use an explicit save dialog. No arbitrary filesystem export command or certificate trust command.

## Security/stability
- CA validation is restricted to the worker's isolated directory and root.crt/root_new.crt. Disable custom certificates for this experimental worker; set private umask on Unix and tighten the root key file. Never export key bytes. Windows private-directory ACL verification remains open.
- Redact only adapter passwords in the existing runtime config/YAML/proxy-chain IPC previews (copies; actual core runtime retains credentials). Normal user proxy data unchanged. Do not treat redacted preview as a loadable runtime file.
- Existing backup creation uses an allowlist that does not include MITM private data. Validate archive entries before restore to reject the reserved private directory and symbolic links. This does not certify pre-existing filesystem aliases, arbitrary diagnostic exports, other logs or service-owned runtime storage. On-disk runtime credentials, trust store installation/removal, CA rotation across separate application sessions and actual desktop TUN still need review.
- No system trust modification, no UI, no release. Previous full network and lifecycle regressions must remain green.
